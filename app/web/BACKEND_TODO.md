## 建議 API 契約草案

以下路徑僅供前後端討論，尚未定案。

| 功能 | 方法與路徑 | 前端需要的回應 |
| --- | --- | --- |
| 取得登入狀態 | `GET /api/session` | 使用者資料與權限 |
| 註冊 | `POST /api/auth/register` | 使用者或驗證狀態 |
| 登入 | `POST /api/auth/login` | 使用者與登入狀態 |
| 登出 | `POST /api/auth/logout` | 成功狀態 |
| 筆記本列表 | `GET /api/notebooks` | 筆記本摘要陣列 |
| 建立筆記本 | `POST /api/notebooks` | 完整筆記本資料 |
| 更新筆記本 | `PATCH /api/notebooks/{id}` | 更新後筆記本 |
| 複製筆記本 | `POST /api/notebooks/{id}/duplicate` | 新筆記本 |
| 刪除筆記本 | `DELETE /api/notebooks/{id}` | 成功狀態 |
| 取得白板 | `GET /api/notebooks/{id}/workspace` | 節點、連線與版本 |
| 儲存白板 | `PUT /api/notebooks/{id}/workspace` | 新版本與儲存時間 |
| 取得來源 | `GET /api/notebooks/{id}/sources` | 來源摘要陣列 |
| 建立來源 | `POST /api/notebooks/{id}/sources` | 來源 metadata |

| 查詢執行狀態 | `GET /api/runs/{runId}` | 狀態、進度、錯誤與輸出 |
| 建立成果 | `POST /api/notebooks/{id}/artifacts` | `artifactId` 或 `runId` |

## 交接原則

前端與後端串接前，每個 API 至少需要以下資訊：

- Request method、path、headers 與 body。
- 成功 response 範例。
- 驗證失敗、權限不足、資料不存在、驗證錯誤與伺服器錯誤格式。
- 非同步工作狀態與錯誤格式。
- 分頁、排序與篩選方式。
- 時間格式、時區與檔案網址期限。
- 對應的前端 loading、empty、error 與 retry 狀態。

後端尚未完成時，前端可以使用 mock service，但 mock response 應與最終 API 契約一致，避免串接時重寫整個畫面。
